## cbom-scout v0.1.0 — 첫 공개 버전

저장소의 암호자산을 자동으로 찾아 **CycloneDX 1.6 CBOM**을 만들고, **NIST IR 8547** 기준으로 PQC 전환 대상을 판정하는 도구입니다.

### 주요 기능
- **소스코드 스캔:** Python, Java/Kotlin, Go, JS/TS, C/C++(OpenSSL), C#의 암호 API 호출 탐지 (알고리즘·키 길이·곡선·모드)
- **설정 파일 스캔:** nginx `ssl_protocols`·`ssl_ecdh_curve`, sshd `KexAlgorithms`·`HostKeyAlgorithms`
- **인증서·키 파일 스캔:** PEM/DER 인증서, 공개키·비밀키, SSH 공개키 (키 값은 기록하지 않음)
- **커밋된 비밀키 탐지:** 저장소에 들어간 `PRIVATE KEY` 블록을 즉시 실패로 처리
- **TLS 엔드포인트 스캔:** TLS 버전·암호 스위트·서버 인증서, OpenSSL 3.5 이상이 있으면 하이브리드 PQC 키 교환(X25519MLKEM768) 협상 여부
- **정책 기반 판정:** 내장 정책 `nist-ir8547`(기본)·`strict`, JSON 정책 파일로 사용자 정의
  - 취약 암호(MD5, SHA-1, 3DES, RSA-1024, ECB, TLS 1.0/1.1)는 즉시 실패
  - 양자 취약 공개키(RSA, ECC, DH)는 경고 → **2031-01-01부터 자동 실패**
  - KpqC 4종(SMAUG-T, NTRU+, HAETAE, AIMer) 양자내성 판정
- **리포트:** 마크다운·HTML, GitHub 작업 요약, 코드 줄 주석(annotation)
- **제외 패턴:** `--exclude` 옵션과 `.cbomignore` 파일로 테스트·예제·생성물 경로를 스캔에서 제외
- **CBOM 병합:** 여러 저장소나 다른 도구(CBOMkit 등)의 CBOM을 합쳐 한 정책으로 평가
- **GitHub Action:** `uses: Why-N0T-ME/cbom-scout@v0.1.0`

### 사용 예
```yaml
- uses: actions/checkout@v4
- uses: Why-N0T-ME/cbom-scout@v0.1.0
  with:
    path: .
    policy: nist-ir8547
    fail-on: fail
```

### 알려진 한계
- 소스코드 분석은 정규식 기반이라 변수로 전달되는 알고리즘 이름은 추적하지 못합니다.
- TLS 하이브리드 키 교환 확인은 OpenSSL 3.5 이상이 필요합니다.
- 클라우드 KMS, SSH 엔드포인트, 컨테이너 이미지 스캔은 다음 버전에서 다룰 예정입니다.

요구 사항: Python 3.10 이상
